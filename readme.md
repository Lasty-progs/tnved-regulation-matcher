# Сопоставление таможенных деклараций и регулирующих НПА

## 1. Принятый подход

Для решения задачи разработан двухуровневый гибридный конвейер поиска и ранжирования:

1. **Sparse Retrieval**:
   - Обеспечивает точный лексический матчинг ключевых терминов, химических названий (уран, нептуний, хладоны), артикулов, номеров решений (КЕЭК №30, Указ №1661) и стандартов.
2. **Dense Semantic Retrieval (SentenceTransformer: `BAAI/bge-m3`)**:
   - Преодолевает проблему несовпадения словарей (*Vocabulary Mismatch*): связывает развернутые коммерческие спецификации товаров (например, *«СХД, накопители SSD, интерфейс SAS, FC»*) с обобщенными правовыми формулировками контролируемых списков (*«технические средства криптографической защиты информации»*).
3. **Доменный бустинг через классификатор ТН ВЭД ЕАЭС**:
   - Справочник ТН ВЭД (все 21 раздел и 97 групп) используется как семантический мост. Регуляции, привязанные к группе товара (например, группа `84/85` для вычислительной техники или группа `02` для мясных квот), получают приоритетный весовой коэффициент (+20%), а нерелевантные группы пенализируются.
4. **Слияние скоров (Score Fusion)**:
   - Линейная нормализация оценок обоих движков с весами $Score = 0.6 \cdot Dense + 0.4 \cdot Sparse + \text{Domain\_Boost}$.
   - Сортировка по убыванию, отбор ровно 10 уникальных регуляций на декларацию с рангами от 1 до 10.

## 2. Рассмотренные альтернативы и компромиссы

- **Чистый BM25 / TF-IDF**:
  - *Плюс*: Сверхбыстрый, не требует памяти.
  - *Минус*: Ошибается при описательном изложении товара и не находит нормативные акты, где те же сущности названы иными терминами.
- **Cross-Encoder Reranker**:
  - *Плюс*: Максимальное качество сопоставления контекста.
  - *Минус*: Превышает лимит времени инференса на CPU при большом числе кандидатов.
- **Выбранный компромисс (Hybrid Bi-Encoder + BM25 + ТН ВЭД бустинг)**:
  - Оптимальный баланс качества и скорости.

## 3. Сложности анализа и методы их решения

1. **Асимметрия текстов и технический шум**:
   - В графе `G31_1` содержится масса артикулов, габаритов, частот и служебных серийников. Реализован модуль `TextCleaner`, удаляющий длинные серийные номера и юридические ссылки в скобках вида `(см. р.1.1 прил.1 к ркеэк №30)`, оставляя чистое смысловое ядро.
2. **Смешанный язык**:
   - Технические товары содержат кириллицу и латиницу (*«SSD, SAS, 12 Гбит/с, PCI-E»*). Использована многоязычная модель `multilingual-e5`, корректно кодирующая двуязычные технические термины в единое векторное пространство.
3. **Строгий контроль валидации**:
   - Модуль `src/utils/validator.py` гарантирует 100% соблюдение формата: ровно 1510 строк, отсутствие дублей `regulation_id`, непрерывные ранги 1–10 для каждой декларации, отсутствие пустых и неконечных значений `score`.

## 4. Инструкция по установке и запуску

### 4.1. Запуск инфраструктуры (БД PostgreSQL + pgvector)
```bash
docker compose up -d
```

### 4.2. Установка зависимостей (однократно):
Используемая версия python - 3.12.14
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```
### 4.3. Предварительное скачивание модели:
```bash
python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('BAAI/bge-m3')"
```

### 4.4. Первичная инициализация и загрузка данных (ETL)
Выполните скрипты наполнения базы данных (парсинг классификатора ТН ВЭД и регуляций):

```Bash
# 1. Парсинг и загрузка полного дерева ТН ВЭД (все 21 раздел и 97 групп)
python scripts/load_tnved.py

# 2. Очистка и загрузка базы нормативно-правовых актов
python scripts/load_regulations.py

# 3. Векторизация категорий ТН ВЭД и семантическая линковка
python scripts/embed_and_link.py
```

### 4.5. Контрольный запуск инференса
```bash
python run.py --out ./out
```
Важно: В конфиге прописанны такие расположение фалов и их имена:
```json
data:
  declarations_path: "input_data/declarations.jsonl"
  regulations_path: "input_data/regulations.jsonl"
  tnved_dump_path: "input_data/tnved_knowledge.txt"
```
